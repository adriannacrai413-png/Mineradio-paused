# 桌面歌单 / 喜欢音乐小窗方案（理解确认版）

## 我对需求的理解

在 Mineradio 的 Windows 桌面模式中增加一个可选的音乐小窗入口：

- 从现有账号同步结果中读取“我的歌单”和“喜欢的音乐”。
- 在桌面形成一个可移动、可缩放、带亚克力玻璃质感的小窗口。
- 小窗显示歌单封面、名称、歌曲数量和若干歌曲；点击歌曲可播放，点击歌单可打开完整歌单。
- 主页面增加一个小窗口图标作为功能入口，入口状态能反映小窗已开启/已隐藏。
- 小窗支持置顶、关闭、临时穿透和记住位置；重启后按设置恢复。
- 视觉上参考仓库中的 702 KB 截图：深色半透明面板、圆角、细边框、封面缩略图、青绿色高亮，叠在桌面背景/壁纸之上。

## 当前工作区已完成的实现

工作区已经完成一版可发布的“桌面歌单小部件”实现，涉及：

- `desktop/main.js`：创建透明置顶小窗和 IPC。
- `desktop/widget-preload.js`：小窗桥接。
- `public/desktop-playlist-widget.html`：队列 / 我的歌单列表和播放控制。
- `public/js/modules/10-shell/06-desktop-widget-bridge.js`：主窗口状态推送和入口按钮。
- `public/index.html`、`public/css/index.css`：右上角入口图标。
- `desktop/main.js`：完整/迷你模式的独立尺寸与位置持久化、自动切换、IPC 来源校验、快捷键和监听器清理。
- `public/desktop-playlist-widget.html`：独立歌词页、翻译歌词、YRC 逐字高亮、迷你模式单行歌词和圆角玻璃面板。
- `tests/desktop-playlist-widget.test.js`：覆盖结构、歌词、尺寸边界、IPC 信任来源和发布身份。

剩余工作主要是发布者本机验收：真实登录账号下检查歌单同步、拖动/缩放、重启恢复，以及不同 DPI/多显示器环境。

## 建议增加的技能

当前没有必须安装的新技能，现有 Electron / CSS / SVG 能力足够完成首版。为了后续重复开发更稳定，建议增加一个项目级技能：

`electron-desktop-widget`

内容应固定记录：Electron `BrowserWindow` 透明置顶窗口、preload IPC 白名单、Windows 桌面模式的图标遮罩、位置持久化、低配置降级和 smoke test 流程。`imagegen` 只适合后续需要生成封面、背景或宣传图时使用；这次界面草图用 SVG 生成，文字和尺寸更可控。

## 建议的第一版交互

1. 主页面右上或桌面模式控制器旁增加“桌面歌单”图标。
2. 点击后打开小窗；首次打开默认显示“我的歌单”，顶部可切换“喜欢的音乐”。
3. 小窗标题栏显示：拖动区域、锁定/穿透、刷新、关闭。
4. 歌曲行点击播放；右键或更多按钮提供“加入队列 / 打开歌单”。
5. 小窗位置和尺寸写入 `userData`，再次打开恢复。
6. 没有登录数据时显示空状态，并提供“去登录 / 刷新同步”入口。

### 响应式尺寸规则

- 小组件高度缩到 `180px` 或以下时自动进入迷你播放器。
- 迷你播放器固定高度约 `140px`，只允许横向调整长度；宽度范围约 `280px–720px`。
- 迷你模式显示封面、歌曲名、当前歌词和核心播放控制，隐藏歌单列表。
- 完整模式和迷你模式分别保存最近一次的尺寸与位置；切换内容或重启后恢复对应状态。

## 建议的数据边界

- 小窗只接收已经存在的统一歌曲对象：`provider/source/id/name/artist/cover/duration`。
- “喜欢的音乐”优先映射为平台返回的特殊歌单；若平台只返回红心集合，则在渲染层归一化为虚拟歌单。
- 网络刷新失败时保留最近一次成功快照，并显示“上次同步时间”。
- 不在小窗中重新实现登录、音源搜索或播放解码。

## 需要你确认的 5 个问题

1. 小窗是否只在 Mineradio 的“桌面模式”出现，还是普通窗口模式也能打开？
2. “我的歌单”要合并哪些来源：全部平台、只保留当前登录平台，还是只显示内置歌单？
3. 你希望“喜欢的音乐”显示为独立标签，还是和我的歌单并排显示为两个桌面小窗？
4. 小窗是否需要直接播放控制（上一首、播放/暂停、下一首），还是首版只点击歌曲播放？
5. 入口图标希望放在主页面哪个区域？我在效果图中暂放在右上角桌面控制器旁。
